Слияние использует игровой `EvolutionRecipes` и не требует дополнительного JS. Добавьте этот файл в пакет с `pack.json`: посадка подсолнуха на двойной горохострел даст `repeater_mgp`.

```json5
// jsons/objects/PlantProps.json5
{
  objects: [{
    objclass: 'PlantProperties',
    aliases: ['repeater'],
    objdata: {
      EvolutionRecipes: [{
        Name: 'my-pack:repeater-fusion',
        OtherPlantType: 'sunflower',
        TargetPlantType: 'repeater_mgp',
        MaxCount: 1,
      }],
    },
  }],
}
```

- `OtherPlantType`: тип высаживаемого растения; `TargetPlantType`: результат.
- `Name`: группа ограничения. При превышении положительного `MaxCount` более ранние слияния в группе возвращаются к исходным типам. Несколько рецептов могут иметь общую группу.
- `ReadOthersCostume`: использует костюм добавленного растения; убедитесь, что пользовательский результат его поддерживает.
- Порядок растений важен; обратный рецепт задаётся отдельно. Массив `EvolutionRecipes` заменяется целиком. Добавьте исходные рецепты, которые хотите сохранить; пакеты не объединяют рецепты автоматически.

## Пользовательские растения

В [официальном примере](./gp-next-examples.md) рецепты задаются в `properties.EvolutionRecipes` растения внутри `content/entities.json`. Фреймворк хранит эти свойства отдельно; обычные патчи `PlantProps` их не изменяют.

Используйте зарегистрированный нативный codename, а не локальный ID, `пакет:id` или числовой ID. Зарегистрированное имя можно посмотреть в Данных. Для `pulse` официального пакета:

`gpn_6578616d706c652e656e746974792d636f6e74656e74_70756c7365`

Его можно указать в `OtherPlantType` или `TargetPlantType`. Объявите зависимости для ссылок на другие пакеты и включите необходимые фреймворки, поведение и ресурсы. Рецепт сам по себе не создаёт ресурсы растения. После изменения свойств или рецептов импортируйте пакет заново и перезапустите игру.
