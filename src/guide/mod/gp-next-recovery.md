## 诊断

“诊断”集中显示模组错误和共享 Hook 信息，提供重启、以安全模式重启、日志和报告导出。日志可按级别或关键词筛选。

报告默认隐藏敏感信息。关闭过滤会保留完整错误消息，可能含路径或模组写入的设置、存档片段；分享前检查。报告不会主动收集游戏存档全文。

## 安全模式

不加载模组，使用现有存档的临时副本，本次进度不保存。可正常重启退出，也可返回恢复页继续处理。

## 启动失败

失败后自动进入恢复页，先备份当前存档和配置，再开放修复操作。按页面推荐操作排查；错误原文可在“错误详情”查看。

| 操作 | 影响 |
| --- | --- |
| 安全模式启动 | 使用临时存档，无模组，本次进度不保存 |
| 恢复上次配置 | 恢复上次成功应用的模组配置，保留当前存档 |
| 重置 GP-Next 设置 | 恢复偏好和实验选项默认值，保留存档、模组文件和启用配置 |
| 恢复配置与存档 | 仅在有对应有效备份时提供；所有玩家进度回退到备份，当前存档另行备份 |
| 导出存档 | 保存当前原始游戏存档，内容损坏时也可导出 |
| 导出诊断 | 保存错误与启动信息，可选择过滤 |

备份失败时不会执行重置或恢复。存档依赖缺失时，应补回对应模组；恢复页不会自动删除未知植物或僵尸。恢复存档不回退模组自有文件。

恢复快照位于应用数据目录的 `gp-next/save-backups/startup-recovery/`；它保存的是进入恢复页时的数据，不一定是故障前的正常状态。原生存档备份位于 `gp-next/save-backups/native-player/`。不要在游戏运行中手动覆盖存档。
