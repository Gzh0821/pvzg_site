# 官网工具 0.16.1 兼容检查

日期：2026-10-24。游戏来源为本地提取的 0.16.1 本体；在线游戏主脚本也已校验为相同 SHA-256：`f48e550d7a7f0845651e59e7d2dbe3d7ccc0eefbd326fdf742c5709fcdfc8e22`。

## 更新内容

- 工具共用版本号由 0.15.0 更新为 0.16.1，存档与键位编辑器共用该配置。
- 无尽进度原先只绑定 `worldProps[id].endlessProps`，0.16.1 原生存档使用顶层 `player_dangerroom[codename]`，导致新版存档没有无尽等级输入。现在编辑实际存在的字段；旧存档仍按游戏迁移优先级读取旧字段。新建存档使用当前 `player_dangerroom` / `player_dangerroom_minigame` 结构，不再注入旧无尽字段。
- 逐份比较 40 份共用游戏 JSON，均与 0.16.1 一致，没有新增植物、僵尸或工具需要的字段，因此不重复改写数据文件。
- 实际读取 0.16.1 花园运行时的花盆顺序、地形和初始解锁状态，四个花园分别为 48、24、14、48 格，与现有布局完全一致。0.16.0 的对应 prefab（`assets/resources/import/02/026362a3b.json`）与新版相同。花园编辑明确支持已核对的 0.15.0、0.16.0、0.16.1，保留对未知版本的限制。
- 植物解码校验原先写死 Cocos 序列化类型索引 20，新版该索引为 21。改为按资源名及数据形状识别，仍将完整数据与本体严格比较。10 个基础植物、45 条合成规则均未变化。
- 下载信息采用官方 0.16.1 Links 数据与四个桌面包地址，继续过滤此前要求移除的三条 Electron 存档目录迁移说明。GP-Next 版本独立维护。

## 存档实际回导

没有只以 `JSON.parse` 成功作为兼容结论。测试使用官网页面的真实导入/导出控件，捕获其下载 Blob，随后通过 0.16.1 游戏自带的 `PlayerSelector.importPP` 文件输入、FileReader 和存档切换逻辑导入。所有测试均在隔离浏览器存档中进行。

| 场景 | 结果 |
| --- | --- |
| 线上旧工具新建的 0.15.0 存档导入 0.16.1 | 成功加载，并由游戏更新存档版本 |
| 0.16.1 游戏导出 → 线上工具解析、导出 → 游戏回导 | 成功加载并进入禅境花园，无捕获错误 |
| 本地更新后的工具新建 0.16.1 存档 → 游戏导入、切换 | 成功，游戏玩家列表正常生成 |
| 复杂存档解析、修改金币、添加并成熟花园植物 → 游戏回导 | 成功；游戏花园实际生成 1 株豌豆射手 |
| 当前结构无尽等级 7 → 12 → 游戏回导 | 成功；顶层埃及无尽等级为 12，未注入旧字段，未知字段完整保留 |
| 旧结构无尽等级 9 → 14 → 游戏回导 | 成功；游戏迁移到顶层结构，等级 14、小关卡等级 3 均保留 |
| 更新后的新建存档（28 个世界的当前无尽结构）→ 游戏回导 | 成功；版本 0.16.1，无尽与小关卡初始等级均为 1 |

复杂存档同时检查了票券、经验、GitHub 关卡路径及记录、无尽进度、禁用升级和未知嵌套字段。回导后票券 7、经验 120、埃及无尽等级 7、升级禁用状态及自定义字段均保留。测试中重复的存档名由游戏界面自动加引号区分，未影响导入。另测中文存档名和文件名、Windows CRLF 与 UTF-8 BOM，均被同一游戏导入流程接受；这仅验证文件内容格式，不代表在 Windows 系统上运行了测试。

这组验证没有复现玩家报告中的导入失败，因此不能宣称已修复该报告的具体原因；仍需失败存档或错误文案才能针对性复现。已修复的是已确认的无尽结构适配、工具版本过期、花园版本限制和解码校验失配。浏览器验证覆盖游戏同一份 JavaScript 导入逻辑，不代替 Windows 文件选择器或桌面原生路径的实测。
