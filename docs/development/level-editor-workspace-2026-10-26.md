# 关卡编辑器工作区与 0.16.1 兼容性

2026-10-26。本轮目标是缩短常用编排路径、统一 Gardenest / 新存档编辑器的材质与层级，并保证普通编辑不会破坏导入关卡的原始语义。改动位于官网仓库；游戏构建产物仅用于审计与运行验证，未修改。

## 为什么玩家可能更偏好 NLM

重新核对了 [NLM 源码](https://github.com/Osamah2004/nlm)，当前 `src/App.jsx` 标识版本 1.3.1（blob `c915bad2ee88dbe0d9ecac46a53d5c7a1299f6db`）。其 React Flow 波次节点、独立棋盘节点、功能快捷键、对话入口和数据导出，使常用操作更容易在同一工作环境中完成。源码也包含传送带、剧情和多种小游戏生成逻辑。

官网已有棋盘、目标、动态僵尸池、事件动作及原始字段保留能力，但原来的长页和重复属性面板把这些能力分散了：使用者需要滚动找功能，再进入多层折叠区。频繁添加僵尸缺少直接指定行和最近素材快捷键，页面刷新也不能恢复完整工程。另一类问题来自导出：界面里只改描述，也可能补入原本不存在的默认值、改动注释和模块引用。这会直接损害作者对工具的信任。

这是对源码和实际操作路径的判断，尚无用户任务完成时间或满意度对照实验；不能据此声称整个官网编辑器已经优于 NLM。

## 本轮实现

- 用“基础 / 棋盘 / 波次 / 卡组”四个工作区替代长页定位；页签支持方向键、Home / End 和对应 ARIA 关系。
- 桌面采用素材库与当前编辑区并列布局；手机通过底部素材抽屉选取，选完返回编辑区。
- 顶部保留校验、撤销重做、预览和导出；导入、工程备份、新建集中到文件菜单。校验详情进入独立窗口。
- 波次卡片显示出怪数量与主要种类；可选定行，或直接点对应行的加号。最多 12 个最近僵尸使用 `1234567890QW` 快捷键，输入框和弹窗不被抢键。
- 事件添加直接选择类型；传送带配置使用植物 / 规则 / 波次三个页签，取消多余的高级折叠层。
- 撤销重做保留当前波次展开状态和棋盘选择。引用型波次转换为静态编排需要明确确认，并能撤销。
- 主面板、菜单、窗口和抽屉使用青绿 / 薄荷配色与磨砂玻璃，输入内容保留清楚的对比度；支持深色、减少动画、减少透明度与高对比度偏好。
- 自动保存整个草稿、原始导入快照和工作区状态；编辑后延迟 350ms 写入，离开页面前补存。工程文件可备份并重新导入。
- 损坏的本地工程不会被自动保存覆盖，可以先下载原始内容；存储失败提供直接备份操作。

## 0.16.1 审计与修复

依据本地已更新的游戏本体、导出的逻辑 JSON 和原生关卡导入口。`assets/main/index.js` SHA-256：

```text
f48e550d7a7f0845651e59e7d2dbe3d7ccc0eefbd326fdf742c5709fcdfc8e22
```

本体包含 659 个 System.register 模块。整文件 REA 分析达到资源上限，本轮改为读取具体模块，包括 `levelController.ts`、`Conveyor.ts`、`NPC_Controller.ts` 和 `PlayerProperties.ts`；不宣称完成了整个游戏的逆向审计。

| 问题 | 修正 |
| --- | --- |
| 场景枚举漏项 | 补齐 8 个场景，编辑器覆盖 `LevelModules` 全部 52 个 LawnType 场景 ID；飞船外场景不生成割草机 |
| 仅改描述却注入默认阳光、改写注释和引用 | 名称、描述、作者、初始阳光单独编辑时只更改对应定义字段；其他编辑也保留未改动定义字段的原始存在性和值 |
| 波次模块被假定为 `NewWaves` | 保留导入的模块别名、外层字段与实际引用 |
| 原版 `EgyptSeedBank` 等卡组别名被替换为 `SeedBank` | 保留实际卡组别名和引用；卡组内容修改时也保留对象外层字段与 `CardDecks` 等扩展 |
| 工程恢复后原始格式保护失效 | 工程同时保存导入源与比较基线，恢复后仍按相同规则导出 |

40 份官网共享游戏 JSON 与当前本体导出数据逐项比较一致。出怪行在本体内部按 `Row - 1` 使用；界面沿用 1–5 行，任意行继续省略 Row。原先已对齐的波次点数、血量阈值、卡槽和倒计时语义保持不变。

## 广告

四种语言的原有响应式手动广告位移到完整工作区之后，与操作区域保持留白。按用户要求，页面不额外添加广告文字、边框或独立分区；Google 广告自身的标识保持原样。保留原发布商和广告位 ID；不浮动、遮挡、裁切、自动刷新广告，也不将广告伪装成素材或按钮。

遵循 [Google 广告展示位置政策](https://support.google.com/adsense/answer/1346295?hl=en)。工作区玻璃效果不作用于广告内容。[自动广告设置](https://support.google.com/adsense/answer/9305577?hl=en) 中，区域排除只覆盖页内广告；要避免编辑时出现覆盖类自动广告，使用关卡编辑器页面的 [网页排除](https://support.google.com/adsense/answer/9262311?hl=en)。这不等于 Google 对布局作出了审核批准。

按用户最新要求，AdSense 后台由用户之后验证。本轮未点击“应用到网站”，未提交后台设置；预览窗口已关闭。代码层面仅调整手动广告的布局，并提供稳定的 `#level-editor-workspace` 作为后续区域排除定位。自动广告的位置仍取决于发布商后台，不能用隐藏、移除或覆盖广告的 DOM / CSS 补丁代替正规排除设置。公开 `pvzge.com/ads.txt` 已核对，含官网发布商的 DIRECT 记录。

## 后续验收边界

当前优先完成常用工作流和导入保真。剧情、多套推荐 / 挑战卡组、生成器构建、僵王与特殊小游戏的完整可视化入口仍需后续分批实现；现有未知内容按原始对象保留。下一批应优先做多套卡组与剧情，再扩展模式专用面板，每批都配真实关卡与本体导入验证。

本轮实测覆盖了关卡读取和进入战斗，不等于完整通关，也未覆盖所有场景、全部事件组合或 Windows 原生桌面运行。浏览器中的 GP-Next 云后台记录了缺少 Tauri API 的错误；该路径独立于本轮关卡导入，原生云功能不在本轮验证范围。上述验收在本地进行，生产发布以对应提交的部署记录与线上检查为准。测试开发服务器已停止，一次性审计文件、下载样本和截图已清理。
